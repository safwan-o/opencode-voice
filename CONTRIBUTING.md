# Contributing

Thanks for helping improve `opencode-voice`. This project follows standard
open-source practices: small focused branches, conventional commits, review
via pull request, and a green test gate on every change.

## Setup

- Use Node.js 20 or newer.
- Clone and install:
  ```bash
  git clone https://github.com/safwan-o/opencode-voice.git opencode-voice
  cd opencode-voice
  npm install
  ```
- No build step: runtime code ships directly from `index.js`, `src/`, `lib/`,
  and `bin/`. (The optional GGUF runtime is a Rust sidecar built separately
  by the Engine Release workflow: `cargo check --manifest-path sidecar/Cargo.toml`.)

## Workflow

1. **Branch** from `main` with a scoped name:
   `feat/<thing>`, `fix/<thing>`, `docs/<thing>`, `chore/<thing>`, `test/<thing>`.
2. **Keep it small.** One branch = one concern. Split independent changes
   instead of stacking them.
3. **Commit** with [Conventional Commits](https://www.conventionalcommits.org/):
   `feat(keymap): ...`, `fix(dialog): ...`, `docs(readme): ...`,
   `test(races): ...`, `chore(release): ...`. Imperative mood, no trailing period.
4. **Open a PR** against `main` with what changed, how it was verified, and any
   known limitations. Small PRs get reviewed fastest.
5. **Merge when green.** `main` must always pass the gate below. Delete the
   branch after merging.

## Quality gate (must pass before every PR)

```bash
npm run check     # node --check on all JS + full test suite
npm pack --dry-run  # inspect the published file list
```

- **Unit tests** (`test/*.test.js`, run with `node --test`) must be hermetic:
  no network, no binaries, no real clipboard/audio — mock at the seam
  (`ctx`, runtimes, runners are all injectable; follow the existing patterns).
- **Integration tests** that need ffmpeg, sidecar binaries, models, or network
  must **skip cleanly** with a message when the dependency is absent
  (`t.skip("needs ...")`), never fail the suite on a bare machine.
- **Generated fixtures** (`test/fixtures/`) are gitignored and regenerated by
  `scripts/gen-voice-fixtures.mjs`. Never commit audio blobs or user recordings.
  Writes must be atomic (temp + rename) — test files run in parallel.
- Keep `index.js` (legacy V1 entry) behavior-compatible; the V2 load path is
  `./tui` → `src/tui.ts` (`Plugin.define({ id, setup })`).
- Do not add dependencies without calling it out in the PR (native modules
  multiply per-platform install risk).

## Docs expectations

- User-visible behavior changes update `README.md` (English source of truth;
  translated `docs/README.*.md` may lag — note it in the PR).
- Bug investigations with measurements go in `docs/` (see `voice-cleanup.md`
  for the format: claim → evidence → numbers).
- Keep the `tui.json`-is-dead / `opencode plugin add`-is-server-only warnings
  accurate — they bite every new contributor.

## Release checklist

- Update `CHANGELOG.md` (Added/Changed/Fixed under a new version heading).
- Bump `package.json` version (patch = fix, minor = feature; the loader is
  npm-only, so every user-visible change needs a publish to reach users).
- `npm run check` green; `npm pack --dry-run` file list sane;
  `bin/opencode-voice.js` executable in the tarball (`mode: 493`).
- Merge to `main`, tag, `npm publish --access public` (no `--provenance` —
  there is no OIDC provider for local publishes).
- Verify live: point `cli.json` at the new version, **fully quit and reopen
  the TUI twice** (`/restart` does not reload plugin code), confirm no
  `Plugin failed` banner plus the feature at work.
- Create the GitHub release from the matching tag.
- Do not publish prereleases as `latest` unless intentional.
